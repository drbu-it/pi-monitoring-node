## 1. The problem

- Toner, paper and page counts are checked by walking to each printer.
- The Xerox alert emails are either on or off. There is no control over timing.
- Page counts are needed for billing and for deciding which printers to keep.

## 2. What we want

Collect everything a printer can report as data, and see it without being on site.

- Page count and impressions
- Toner level
- Paper, faults and status
- Anything else a model exposes that is useful

**The first version is done when:**

- Every networked DRBU printer reports page count and toner to one place we can open off site.
- A low-toner warning arrives before the toner runs out.
- The manual Printer Check no longer needs a walk-around.
- A monthly print report per location can be produced from the data.

**Who uses it:**

| Output | Used by | For |
|--------|---------|-----|
| Alerts | IT | Knowing what needs attention today |
| Toner levels | IT | Ordering toner in time |
| Monthly counts | IT and billing | Reconciling the print bill, usage by location |

## 3. The idea

```
printers  --SNMP-->  Raspberry Pi (collector)  -->  storage  -->  remote view
                                               \->  alert digest email
```

- The Pi sits on the DRBU network and asks each printer for its numbers on a schedule.
- SNMP is the standard way printers report counts and supply levels.
- **Decided:** we build this ourselves on the Pi. We are not buying a print-management product.
- **Live demo:** one SNMP query against the Xerox, to see what a printer actually answers.

**Also on this Pi later (Frank's part, not yours):**

- UPS monitoring (NUT)
- Camera footage transfer to Google Drive

These shape how the OS is installed, which is why they are mentioned here.

**Related work:**

- Printer replacement is waiting on this project. The data will show which printers are worth replacing.
- The Printer Health Dashboard ticket overlaps with decision 1 below.
